## 2026-10-30 (late night) — Occlusion queries recorded inside render passes: +58%

A guest query becomes one host query per guest render target cache pass it spans (a segment, begun when the pass starts or the query begins inside it, ended when either ends), recorded inside the pass instead of ending it. ## 2026-10-30 (evening) — Real fix: shaders were 10-20x slow from SPIRV-Cross `optnone` helpers
- **Cause:** Xenia's SPIR-V marks most float math `NoContraction`. SPIRV-Cross (inside MoltenVK) emits those operations as calls to `spvFAdd`/`spvFMul`/`spvFSub` helpers declared `[[clang::optnone]]`. Metal cannot optimize or inline them, so shaders reached 146-254 registers with spills and starved Apple GPU occupancy. A standalone harness (`work/experiments/menu-bench/harness/`) times dumped MSL with dummy resources. Stripping `optnone` takes the top menu shaders from 1.0-2.9 ms per full-screen draw to 0.09-0.31 ms.
- **Changed:** SDK patch `0009-contract-shader-math.patch`. `vulkan_contract_pixel_shader_math` and `vulkan_contract_vertex_shader_math` (defaults false in the SDK) skip `NoContraction`. The vertex variant decorates the position `Invariant` to avoid multipass z-fighting. The patch also includes experiments that showed no gain: `vulkan_plain_multiply` (skip Xenos 0*x emulation) and `vulkan_assume_unsigned_textures`. **Both contraction switches are enabled in the app bundle's `crackdown.toml`** (local prototype defaults; the repo's `config/crackdown.toml` is unchanged).
- **Measured:** Menu goes from 19-23 to ~61-63 FPS uncapped. Gameplay goes from ~5 to 10-13 FPS in the garage, ~8-10 FPS in the city, peaks of 22. Bruce saw correct rendering, including the city and no z-fighting. Remaining sub-8 FPS dips line up with first-use pipeline compilation.
- **Bugs seen:** The game froze with audio running after the window went fullscreen during a capture-enabled run. That run combined `MVK_CONFIG_SHADER_DUMP_DIR` with the capture variables, and MoltenVK then wrote the trace to an invalid path (the dump directory), so the freeze may be specific to that setup. Do not combine those variables. Pre-existing black/flashing title on about half of launches; relaunch.
- **Next:** Profile a gameplay frame with the fix (capture without shader dump) and rank shaders with the harness on gameplay MSL dumps. Reduce compile hitches (pipeline precompilation/storage, `vulkan_async_skip_incomplete_frames`). Consider landing contraction as a Mac default in source and repo config.

## 2026-10-30 (late afternoon) — Root cause: translated pixel shaders need 146-254 registers
- **Measured (Xcode GPU profile of the menu frame, `work/experiments/menu-bench/menu.gputrace`, 68.9 ms GPU):** The top fragment shaders by cost are 36.9% (146 registers, 32 B spilled), 25.6% (204 registers, 32 B), 12.1% (254 registers, 80 B), 2.3% (188) and 2.3% (110). That explains every earlier symptom: GPU busy at ~15% ALU, ~12% occupancy, cost scaling with pixels, and simple post-process shaders taking milliseconds.
- **Ruled out:** `MVK_CONFIG_FAST_MATH_ENABLED=0` is slower (19.1 FPS), so fast math is already on by default. The "1"/"2" runs are invalid because the game entered gameplay mid-run.
